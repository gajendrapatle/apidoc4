1.0.1 API Login

This API endpoint is used to authenticate and obtain an access token required for subsequent API requests to the StAR MF system.

A successful login provides an `access_token` that must be used in the `Authorization` header for all protected API calls.

1.0.2 Submit Payment Aggregation (MIS) Report

This API is used to submit Payment Aggregation (MIS) reports. It accepts a list of objects, each representing a record for the MIS report.

Important: If the same request is submitted more than once for the same `payment_ref_id`, subsequent requests will be ignored. The maximum record level entry limit for API bulk upload is 10,000 records or a maximum file size of 10 MB.

1.0.3 Payment Aggregator Get Details

This API allows you to retrieve details of a previously submitted Payment Aggregation (MIS) report based on a reference ID.

Either `payment_ref_id` or `utrn_no` is mandatory for this API.

Frequently Asked Questions

1. What modes of communication will be used for STAR MF Version 2.0?

The modes of communication for STAR MF Version 2.0 will be SFTP, UI, and API.

2. What modes of communication are currently being used for Version 1.0?

The current modes of communication for Version 1.0 are SFTP, UI and Email.

3. What are the next steps after the demo call?

  • Share the IP address.
  • Post-whitelisting, validate and confirm connectivity.

4. What are the preferred payment settlement modes for Version 2.0?

  • NEFT
  • RTGS
  • Cheque
  • UPI
  • IFT (Internal Fund Transfer)
  • IMPS

5. What type of upload options are available in the API?

Both bulk upload and single upload options are available.

6. What are the MIS types for Version 2.0?

  • XSIP
  • OTM
  • DIRECT
  • NODAL
  • NEFT
  • UPI
  • UPIR
  • NACH
  • CHEQUE
  • ENACH
  • DIRECT DEBIT

7. Is there a limit on the upload size?

  • Upload limit via API: 10,000 records in one go.
  • For CSV files: Up to 10 MB of data can be uploaded through the STAR MF Version 2.0 interface.

8. What needs to be mentioned in the documentation regarding user-defined fields?

Refer to the mode-wise expected documentation and complete the fields accordingly.

9. What should be passed for the exchange order number (exchorder_num) in MIS transactions?

  • For OTM transactions, the exchange order number must be passed.
  • In XSIP transactions, the SIP registration number should be used.
  • For other modes, this field will remain blank.

10. What encryption level is required for JSON/file or data?

No encryption is required unless specified separately.

11. What is the login time interval and frequency?

  • UAT Environment: 30 seconds interval
  • Production Environment: 25 seconds interval

12. What type of API is used in StAR MF Version 2.0?

An asynchronous API is utilized.

13. Will STAR MF Version 1.0 and 2.0 run simultaneously?

Yes, PAs, Banks, and Agencies are hereby advised that, effective immediately, a new Credit MIS file format shall be applicable for reporting under the StAR MF 2.0 platform. Both the existing MIS format for Version 1 and the new Credit MIS format for Version 2 will operate concurrently. It is the responsibility of all reporting entities to ensure accurate and timely submission of transaction data in the respective formats applicable to each version.

14. What are the bank account types available?

  • SB - Saving Account
  • CB - Current Account
  • NR - NRE Account
  • NO - NRO Account
  • OT - Other (Other refers to any account which is not mentioned above)

15. What is the character length for the bank name and account type?

Please refer to the MIS API documentation for details (referencing parameter tables in other sections).

16. Can multiple API requests be sent at once?

Only one API request can be sent at a time.

17. What attributes and character lengths are required for development?

Refer to the MIS API documentation for specific attributes, length, and format requirements (referencing parameter tables in other sections).

18. What is the maximum record level entry limit for API bulk upload?

The limit is 10,000 records in one batch or a maximum file size of 10 MB.

19. What happens if some records are incorrect during an upload?

  • Valid records will be successfully processed.
  • Incorrect records will be rejected.
  • Only the incorrect records need to be corrected and re-uploaded.

20. File name convention for upload and collection file?

  • For Upload: `Agencycode_DDMMMYYYY_0001`
  • For Collection: `C_Agencycode_DDMMMYYYY_0001`

21. How File Upload Handling and Sequential File Naming be in StAR MF Version 2.0?

Consider the below example:

Condition: If a file with sequence number 0001 has already been uploaded or marked as rejected, and the system enforces sequential file numbering.

Expected System Behavior:

  • The system must identify the next available sequence number in the series.
  • It should automatically assign this sequence number when attempting to re-upload the contents of the rejected file.
  • If the same sequence number is reused without proper handling, the system must raise a `Duplicate File Upload` error during the validation stage.
